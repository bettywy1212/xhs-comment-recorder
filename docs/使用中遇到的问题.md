# 使用中遇到的问题记录

（插件名称：小红帽 · 小红书评论记录器，仓库名 xhs-comment-recorder）

这份文档记录真实使用过程中遇到的困惑和问题，用来编写发布到 GitHub 时的使用说明（产品说明手册）和常见问题（FAQ）。

每条记录包含：**遇到了什么** → **原因** → **现在怎么处理** → **说明手册里要写什么**。

---

## 1. 用自动化工具操作浏览器，被小红书风控警告

- **遇到了什么**：之前用自动化工具控制浏览器采集评论，收到了小红书的风控警告。
- **原因**：自动化工具会留下“程序在操作”的痕迹，滚动和点击的节奏也和真人不一样。
- **现在怎么处理**：插件设计成“被动记录”：用户自己浏览，插件只记下页面已经加载出来的数据，不发出额外请求，也不自动操作。
- **说明手册里要写**：开头就讲清楚插件为什么不容易触发风控、需要用户做哪些手动操作，以及“正常节奏浏览”的建议。

## 2. 安装插件后，已经打开的笔记页面记录不到评论

- **遇到了什么**：（预判的问题）插件安装前就打开的页面，滑动评论区也记录不到。
- **原因**：插件只能在页面加载时开始监听。
- **现在怎么处理**：弹窗里会提示“请刷新页面后再滑动”。
- **说明手册里要写**：安装完先刷新小红书页面。

## 3. 插件更新后，新功能“没反应”

- **遇到了什么**：更新插件文件后，点“下载图片”按钮没有任何反应。
- **原因**（没有完全确认，可能是下面两个之一）：
  1. 更新文件后没有在 `chrome://extensions` 里点插件卡片上的 ↻ 重新加载，Chrome 还在运行旧代码。
  2. 评论是用旧版本插件采集的，旧记录里没有图片地址，按钮实际处于不可点状态（显示“0 张”）。
- **现在怎么处理**：
  - “下载图片”功能已改成“导出 Excel”，导出时有进度和结果提示，不会再“没反应”。
  - 弹窗会识别旧版本的记录，提示“缺少图片信息，请删除后重新采集”。
- **说明手册里要写**：
  - 怎么更新插件：替换文件后，到 `chrome://extensions` 点 ↻。
  - 更新后如果提示“来自旧版本”，删除记录后刷新笔记页面，重新滑一遍。

## 4. 希望图片直接出现在表格里对应评论的位置

- **遇到了什么**：图片单独下载到文件夹里，对照起来不方便。希望图片直接在表格中、和评论在同一行。
- **原因**：CSV 是纯文本格式，放不了图片。
- **现在怎么处理**：新增“导出 Excel”，评论图片以缩略图形式嵌在对应评论那一行。
- **说明手册里要写**：Excel 和 CSV 的区别、什么时候用哪个。

## 5. 不用 Excel，而是用 Numbers 或在线表格打开

- **遇到了什么**：使用者平时用 Numbers，或者把文件导入腾讯文档、飞书、Google 表格，而不是用 Excel。
- **原因**：各软件放置图片的方式不同：Excel 按单元格定位，Numbers 按整张表的坐标定位，而且每个软件换算列宽的方式也不一样。图片放在中间的列，在 Numbers 里会和文字叠在一起。
- **现在怎么处理**：图片统一放在第一列（A 列），多张图每行排 3 张；每一行的高度都固定写好。
- **说明手册里要写**：
  - 支持哪些软件打开。
  - Numbers 里第一列显得较宽，可以手动拖窄。
  - 在线表格要用“导入”功能打开 `.xlsx` 文件。（各在线表格的实际效果还需要使用者确认后补充）

## 6. 导出 Excel 时偶尔有 1 张图片加载失败，再导出一次又成功了

- **遇到了什么**：同一篇笔记导出了三次。前两次，33 张图里有 1 张失败，第三次全部成功。
- **原因**：小红书图片服务器偶尔会超时、断开连接，或者短时间内拒绝请求。这是网络层面的偶发问题，不是插件逻辑出错（同一张图后来能成功加载）。旧版本失败了不会重试，所以只要失败一次，这张图就丢了。
- **现在怎么处理**：
  - 每张图片加载失败后会自动重试，最多尝试 3 次（间隔 1 秒、3 秒），每次最长等 20 秒。
  - 重试后仍然失败的图片会降级处理：“图片链接”列里对应的链接前面标上“【未能加载，请手动打开】”；如果一条评论的图片全部失败，图片格里也会写明。
  - 导出完成后，弹窗会告诉你有几张失败、在第几楼。
- **说明手册里要写**：图片加载失败是偶发情况，可以手动打开标注的链接，或者稍后再导出一次。
